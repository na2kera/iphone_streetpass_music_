# レビュー第3回（2026-11-08）統合対応計画

対象コミット: f0f0b33。レビュアー: Codex（medium 2・low 1）、Fable（medium 4・low 5）。high なし。第2回の 10 項目は両者とも実装済みと確認。

## PassbyManager.swift

1. **切断コールバックが来ない経路の救済**（Codex 1, Fable 1）[medium]
   - `finishSession` で `disconnecting[id] != nil` のためスキャン再開を見送る側の分岐で、`deferredPeripherals[id] = (session.peripheral, Date().addingTimeInterval(disconnectWaitLimit))` を登録し `scheduleRediscoveryIfNeeded()` を呼ぶ。
   - `didDisconnectPeripheral` と `didFailToConnect` では `deferredPeripherals[id] = nil` にしてから既存のスキャン再開処理を行う。
2. **「切断待ち」分岐の無期限反復を止める**（Codex 2, Fable 2）[medium]
   - `didDiscover` の「切断待ち」分岐: `disconnecting[id] == nil` かつ `peripheral.state != .disconnected` なら `requestDisconnect(peripheral)` を（再）発行する。deferred の期限は 1 秒ではなく `disconnectWaitLimit` にする。
   - `centralManagerDidUpdateState` の非 poweredOn 分岐で復元 peripheral を捨てるとき、`central.cancelPeripheralConnection` も呼ぶ。
3. **クールダウン 0 分での即時再接続ループ**（Fable 3）[medium]
   - `private let minReconnectInterval: TimeInterval = 5` を追加し、成功時は `nextAllowedAtByPeripheral[id] = Date().addingTimeInterval(max(cooldownInterval, minReconnectInterval))`。
4. **クールダウン変更・通信オフで状態を初期化**（Fable 4）[medium]
   - `setCooldownMinutes` で `nextAllowedAtByPeripheral.removeAll(); deferredPeripherals.removeAll(); rediscoveryTask?.cancel(); rediscoveryTask = nil; rediscoveryFireAt = nil;` の後 `if isEnabled { restartScan() }`。
   - `stopAll()` でも `nextAllowedAtByPeripheral.removeAll()`。
5. **トークン更新の機会**（Codex 3）[low]
   - トークン更新判定を `rotateTokenIfNeeded()` に分離し、`currentPayloadData()` と `beginSession(with:)` の冒頭（セッション登録前）の両方から呼ぶ。抑止条件（`sessions.isEmpty` かつ直近 read 応答なし）は維持。
6. **restartScan のログ**（Fable 7）[low]
   - `restartScan()` を `@discardableResult func restartScan() -> Bool` にし、実際に再開したときだけ `scan/started 再発見のため再開` を記録する。
