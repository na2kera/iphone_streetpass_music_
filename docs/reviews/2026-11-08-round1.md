# レビュー第1回（2026-11-08）統合対応計画

レビュアー: Codex（10件）、Fable（13件）。重複を統合し、以下を全件対応する。
対象コミット: eeb8fbf

## A. PassbyManager.swift

1. **通信オフ後の遅延コールバック遮断**（Codex 1）
   - `didDiscover` は `isEnabled == false` なら無視してログ。
   - `didReceiveRead` / `didReceiveWrite` は `isEnabled == false` なら `.readNotPermitted` / `.writeNotPermitted` を 1 回だけ返す。
   - `stopAll()` は `isAdvertising` に関係なく `peripheralManager?.stopAdvertising()` を呼ぶ（開始要求中も止める）。
   - `peripheralManagerDidStartAdvertising` 成功時に `isEnabled == false` なら即 `stopAdvertising()`。
2. **サービス追加完了後に広告**（Codex 6, Fable 7）
   - サービス状態を `none / adding / added` の 3 値にする。`add(service)` 後は `adding`。
   - `didAdd` 成功で `added` にして `startAdvertising`。失敗は `none` に戻してログ。`restartAll()` で再試行できる。
   - 復元で `added` が分かっている場合のみ即時広告。
3. **クールダウン／バックオフ明けの再発見**（Codex 3, Fable 1）
   - `didDiscover` でクールダウン/バックオフにより捨てたとき、`deferredPeripherals[id] = (peripheral, next)` に保持。
   - 単一の `rediscoveryTask` を、保持中の最も早い `next` まで sleep → `restartScan()` → ログ `scan/started 再発見のため再開` で起動する。既に走っていれば起動しない。
   - `appDidBecomeActive` と `finishSession` 内の `restartScan()` 後に期限切れエントリを掃除する。
   - 背景でタイマーが遅れる可能性はコメントとログで明示する。
4. **復元セッションのタイムアウトと順序**（Codex 4, Fable 2, Fable 4）
   - `beginSession` のタイムアウト生成を `armTimeout(for:)` に切り出す。
   - `willRestoreState` では peripheral を `restoredPeripherals` に保持するだけにする。
   - `centralManagerDidUpdateState(.poweredOn)` で: 各 restored peripheral について `.connected` ならセッション作成 + `armTimeout` + `discoverServices`（`services` が既にあれば `discoverCharacteristics`）、`.connecting` ならセッション作成 + `armTimeout`、それ以外は破棄。その後 `isScanning` に関係なく `restartScan()`。
5. **finishSession の冪等化と切断待ち**（Codex 9, Fable 3a/3b）
   - `finishSession` 冒頭で `guard sessions[id] === session else { return }`。
   - 切断要求を出した peripheral は `disconnecting[id] = peripheral` に保持し、`didDisconnectPeripheral` で除去。
   - `didDiscover` は `disconnecting[id] != nil` または `peripheral.state != .disconnected` なら接続しない（ログ `connect/skipped 切断待ち`）。
6. **成功判定の厳密化**（Fable 5）
   - `success = receivedPayload != nil && wroteOK`。片側のみ成功は `disconnect/failed reason=...` でログし、30 秒バックオフ。履歴は従来どおり `received` で保存。
7. **トークン重複抑制をクールダウン設定から独立**（Fable 3c）
   - `isTokenInCooldown` は `max(cooldownInterval, exchangeTimeoutSeconds * 2)` を窓にする。クールダウン 0 分でも同時接続による二重保存を防ぐ。
8. **stopAll で受信済み未保存を保存**（Fable 9）
   - `sessions` を回す際に `receivedPayload != nil && !saved` なら `saveReceived(status: .received, failureReason: "ユーザーが通信をオフ")`。
9. **発見のみモードの範囲を明確化**（Codex 7）
   - オンにしたとき進行中セッションを `finishSession(success: false, reason: "discoveryOnly")`。
   - Peripheral 側: read は `.readNotPermitted`、write は `.writeNotPermitted` を返しログ。広告は継続（発見率計測のため）。
   - DebugView のラベルを「発見のみ（接続せず、GATT 応答も拒否）」にする。
10. **read ペイロードのスナップショット**（Codex 8, Fable 11）
    - `offset == 0` のとき `currentPayloadData()` を `readSnapshots[central.identifier] = (data, Date())` に保存。`offset > 0` はスナップショットから返す。無ければ `.invalidOffset`。
    - 60 秒より古いスナップショットは次回 `offset == 0` で置き換える。`stopAll()` で全消去。
11. **long write の検証**（Codex 5）
    - 対象外 characteristic が 1 つでもあれば `.attributeNotFound`。
    - offset 順に並べ、先頭 `offset == 0` かつ連続（`offset == buffer.count`）でなければ `.invalidOffset`。
    - 合計が `maxPayloadBytes` 超なら `.invalidAttributeValueLength`。
12. **セッショントークンのローテーション**（Fable 10）
    - `sessionToken` を `private(set) var` にし、`tokenCreatedAt` を持つ。`currentPayloadData()` 呼び出し時に 60 分を超えていれば再生成してログ。
13. **AppDelegate の削除**（ビルド警告）
    - `launchOptions[.bluetoothCentrals/.bluetoothPeripherals]` は iOS 26 で非推奨。AppDelegate を削除し、復元起動の根拠は `willRestoreState` のログに統一する。`AppServices` も不要なら削除。

## B. SongPayload.swift

14. **512 バイト保証**（Codex 2, Fable 8）
    - 縮小は title/artist のうち UTF-8 バイト数が大きいほうだけを縮める。
    - ループ後も超過していれば、UTF-8 バイト境界で固定長（各 120 バイト）に切る最終フォールバック。
    - それでも超過なら URL を落とし、最後は `title` のみの最小ペイロード。関数は必ず `≤ 512` を返す（`assert` ではなく実行時保証）。
    - `SongEditView` で曲名・アーティストは 100 文字、URL は 300 文字に入力制限。

## C. App

15. **ModelContainer 失敗時の扱い**（Codex 10）
    - `fatalError` をやめ、失敗したら `RootView` の代わりにエラー画面（「データベースを開けませんでした」＋エラー文）を表示し、BLE は開始しない。

## D. Logging

16. **ログの保持期間と件数上限**（Fable 6）
    - 起動時に 7 日より古い `DebugEvent` を削除し、さらに 5000 件を超える分は古い順に削除。
    - `DebugView` の `@Query` は `FetchDescriptor` に `fetchLimit = 300` を付ける（件数表示は別途 count を取る）。

## E. Views

17. **SongEditView の初回ロード**（Fable 12）
    - `@State private var loaded = false` で初回のみ `load()`。
