対象コミット: 9a95649。レビュアー: Codex（high 1・medium 3）、Fable（high 1・medium 3・low 5）。重複を統合し全件対応する。
第1回の 19 項目は両レビュアーとも「実装済み」と確認（ただし項目 2・3・5 に下記の不備あり）。

## PassbyManager.swift

1. **切断待ち中の再発見が捨てられ、以後その相手に接続できない**（Codex 1, Fable 1）[high]
   - `finishSession` の末尾で `restartScan()` を呼ぶのは `disconnecting[id] == nil` のときだけにする。切断待ちなら `didDisconnectPeripheral` 側に任せる。
   - `didDisconnectPeripheral` と `didFailToConnect` で、`sessions[id] == nil && isEnabled` なら `restartScan(); purgeExpiredDeferred()` を呼ぶ。
   - `didDiscover` の「切断待ち」分岐でも保険として `deferredPeripherals[id] = (peripheral, Date().addingTimeInterval(1))` を登録して `scheduleRediscoveryIfNeeded()` を呼ぶ。
2. **再発見予約の期限が更新されない**（Codex 2, Fable 2）[medium]
   - `rediscoveryFireAt: Date?` を保持。`scheduleRediscoveryIfNeeded()` で、新しい最短期限が `rediscoveryFireAt` より早ければ既存タスクを cancel して予約し直す。タスク完了・cancel 時に `rediscoveryFireAt = nil`。
3. **古い didAdd 通知を現在の追加完了と誤認**（Codex 3）[medium]
   - 追加中の `CBMutableService` を `pendingService` に保持し、`didAdd` では `service === pendingService`（同一インスタンス）を確認。違えばログして無視。`stopAll()` と状態降格時に `pendingService = nil`。
4. **Bluetooth オフ→オンで GATT サービスが二重登録**（Codex 4, Fable 3）[medium]
   - `peripheralManagerDidUpdateState`: `.poweredOff` では `serviceState` を維持（広告は一時停止扱いで `isAdvertising = false`）。`rawValue < CBManagerState.poweredOff.rawValue`（unknown/resetting/unsupported/unauthorized）のときだけ `.none` に戻す。
   - 保険として `startAdvertisingIfPossible` の `.none` 分岐では `pm.add(service)` の前に `pm.removeAllServices()` を呼ぶ。
   - `.poweredOn` 復帰時に `isAdvertising = pm.isAdvertising` で同期してから `startAdvertisingIfPossible()`。
5. **`disconnecting` が永久に残り得る**（Fable 4）[medium]
   - `disconnecting` を `[UUID: (peripheral: CBPeripheral, requestedAt: Date)]` にする。
   - `didDiscover` で `requestedAt` が 5 秒以上前なら削除して先に進む（ログ `connect/info 切断待ちを期限切れで解除`）。
   - `centralManagerDidUpdateState` の `.poweredOn` 分岐でも `disconnecting.removeAll()`。
6. **Bluetooth オフ時にセッションを畳まない**（Fable 5）[low]
   - `centralManagerDidUpdateState` の非 `.poweredOn` 分岐で `for s in Array(sessions.values) { finishSession(s, success: false, reason: "bluetooth unavailable") }`。
   - `finishSession` で reason が `"bluetooth unavailable"` または `"discoveryOnly"` のときは `nextAllowedAtByPeripheral[id] = nil`（バックオフなし）。（Fable 9 も同時に解決）
7. **トークン更新が接続の途中に入る**（Fable 6）[low]
   - `currentPayloadData()` のトークン更新は、`sessions.isEmpty` かつ `readServedAtByCentral` に `tokenDedupWindow` 以内のエントリが無いときだけ行う。
